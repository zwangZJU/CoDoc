# CoDoc（同写）设计系统 · 设计令牌文档 v1.0

> **产品**：多人实时协同在线办公套件（Web 桌面端），支持 Word 形态（.docx）与 Excel 形态（.xlsx）实时协同编辑
> **主题**：LIGHT FIRST（浅色为主主题；深色仅作 P2 专注模式可选变体）
> **基准**：1440px 桌面优先，1280px 起响应式
> **配套文件**：`tokens.css`（可直接 `<link>` 引入的 CSS 变量块）
> **生成日期**：2026-09-21 · 设计系统专家 彩格调
> **v1.1 修订（2026-09-21）**：① §6.11 段落锁竖条改为「淡底**左外侧**」（采纳原型实现，理由已写入）；② §6.5 / §11.1-3 新增「**协同色底 + 白字**必须用 `-ink`」规则（与"禁止主色写文字"同一根因的第二个触发面）。

## 0. 品牌名建议（附加交付）

用户给了 "CoDoc" 作为暂定名，并允许提出更合适的名字。**建议采用双名制：中文「同写」+ 英文 CoDoc。**

| 候选 | 中文 | 英文 | 评价 | 结论 |
|------|------|------|------|------|
| **A** | **同写** | **CoDoc** | "同"直指协同，"写"直指动作；双音节、无生僻字、拼音 **tóng xiě** 无歧义谐音；"写"天然覆盖"写材料"与"对数据"两种形态（表格也是"写"） | ★ **推荐** |
| B | 共笔 | CoPen | 有文气、记忆点强，但"笔"偏向书写，Excel 形态叫"笔"略违和 | 备选 |
| C | 协写 | CoWrite | 语义最精准，但"协写"口语不顺，CoWrite 6 字母偏长 | 备选 |

**推荐方案**：对外中文品牌名「**同写**」，英文标记保留 **CoDoc**（短、域名友好、工程代号沿用）。Logo 文字标记为「同写 CoDoc」。
产品内部用「**文档**」与「**表格**」区分两种形态，品牌层由「同写」统摄 —— 这样既解决 "Doc" 无法覆盖 Excel 形态的问题，又不动既定代号。

## 1. 设计系统选型

### 1.1 候选对比

| 方案 | 设计系统 | 匹配度 | 核心特征 | 为什么适合 / 需要接受什么取舍 |
|------|---------|--------|---------|---------------------------|
| **A** | **Stripe**（主干）<br>＋ Notion 排版<br>＋ Linear 细节 | ★★★★★ | 中性灰阶克制、1px 细线、几乎不用阴影、专业金融级严谨、表格密度控制业界最佳、单一强调色体系 | **首选。** 用户描述的"白/浅灰底 + 单一强调蓝 + 6–8px 圆角 + 1px 细分隔线 + 几乎不用阴影"几乎就是 Stripe 的设计宣言原文。Stripe 同时拥有**文档型页面**（宽版心、宽松排版）与**数据表格**（紧凑行高、清晰网格线）两套成熟密度方案，正好对应本项目 Word / Excel 双形态。<br>**取舍**：Stripe 原生圆角偏小（4–6px），本项目放宽到 6–8px；Stripe 本身没有多人协同语义，协同 6 色体系需另行注入（本令牌已补齐）。 |
| **B** | **Notion**（纯血） | ★★★★☆ | 白纸画布、温和灰阶、内容优先、极强的"让人忘记界面"感、中文排版友好 | 文档编辑器场景的天然答案，协同底色（标注/提及）有现成语言，非技术人员受众零学习成本。<br>**取舍**：信息密度偏低，Excel 表格场景需要额外定义紧凑节奏（Notion 的数据库视图偏卡片化，不是电子表格）；纯灰阶容易显得寡淡，需要强调蓝提神；圆角偏小且组件语言偏"朴素"，工具栏/权限面板这类 chrome 的精细度不足。 |
| **C** | **Linear** | ★★★★☆ | 1px 边框精度极高、微阴影克制、控件紧凑、状态点/描边语言成熟、focus ring 业界标杆 | 细部精度是三家里最好的，"小圆点 + 细描边 + 紧凑控件"的语言**正是协同光标 / 单元格占用描边 / 呼吸点最需要的**。密度天然偏紧凑，适合 Excel 场景。<br>**取舍**：Linear 默认深色为主，本项目需整体反转为浅色（工作量大且容易反转不到位）；气质偏"开发者工具"（冷峻、字号偏小），对非技术人员受众偏冷；排版偏西文，中文行高需重做。 |

### 1.2 落选说明（为什么不是它们）

- **Airtable / ClickHouse / MongoDB**：表格与数据密度极强，但整体气质是"数据库工具"，与"写材料"的文档场景割裂。
- **Figma**：协同可视化鼻祖（彩色光标、头像组），但其界面是深色工具感 + 高密度面板，与"克制专业办公感"冲突；仅借鉴其**协同光标表达**。
- **IBM Carbon**：企业级办公、可访问性最强、中文（IBM Plex）支持完善，但视觉偏"传统企业软件"，圆角 2px、网格感重，与用户要的 6–8px 圆角调性不符。
- **Google 系**：不在 71 套库内，且本方案 A 已覆盖其"克制办公"内核。
- **Cursor / Vercel / Supabase**：开发工具属性过强，默认深色，排除。

### 1.3 首选方案定义

> **Stripe-led Restrained Office（克制办公）**
> 以 Stripe 的**中性色阶 / 边框哲学 / 阴影克制 / 表格密度**为骨架；
> 以 Notion 的**白纸画布 / 温和排版 / 中文行高 1.75** 为血肉；
> 以 Linear 的**控件精度 / focus ring / 状态点 / 紧凑 chrome** 为细节。

**视觉方向坐标**：Modern Minimal（5 大方向中的第 2 个）—— 拒绝 Editorial 的装饰感、Tech Utility 的暗色霓虹、Brutalist 的粗野、Soft Warm 的圆润渐变。

## 2. Visual Theme（视觉主题）

**Philosophy**：让人忘记界面 —— 所有视觉重量都让给内容和"谁在改哪里"。

**Direction**：`restrained · utilitarian · light · precise · low-chroma`

**Personality**：专业、克制、可信、不抢戏。像一张干净的办公桌，而不是一个设计作品。

**Reference**：Stripe Dashboard 的中性克制 × Notion 文档的白纸温和 × Linear 的细节精度。

**三条铁律**
1. **层级靠 1px 线 + 背景色差，不靠阴影。** 全站阴影只出现在下拉 / 抽屉 / 模态三处。
2. **颜色只承担三件事**：品牌与系统态（蓝 / 绿 / 琥珀 / 红）、人（协同 6 色）、内容（文本）。除此之外不出第二种颜色。
3. **协同可视化的表达力优先于极简。** 当"极简"与"看清楚谁在改哪里"冲突时，让极简让步。

### 3.5 协同 6 色（Collaboration）

> 沿用用户既定色板。每个颜色提供 **4 个变体**：主色（描边 / 竖条 / 光标 / 头像底）、ink（文字）、bg（10% 淡底，段落淡背景）、bg-strong（20%，单元格描边底 / 选区）。

| Slot | 名称 | 主色 | 对比度 | ink（文字专用） | ink 对比度 | bg（10%） | bg-strong（20%） |
|------|------|------|--------|----------------|-----------|-----------|-----------------|
| 1 | 深蓝 | `#185FA5` | 6.53:1 ✅ | `#185FA5` | 6.53:1 | `#E8EFF6` | `#D3E2F0` |
| 2 | 琥珀 | `#BA7517` | **3.72:1** ⚠️ 非文本 | `#8F5B08` | **5.73:1** ✅ | `#F8F1E8` | `#F0E2CC` |
| 3 | 青绿 | `#0F6E56` | 6.20:1 ✅ | `#0F6E56` | 6.20:1 | `#E7F1EE` | `#CFE4DD` |
| 4 | 紫 | `#534AB7` | 6.93:1 ✅ | `#534AB7` | 6.93:1 | `#EEEDF8` | `#DCDAEF` |
| 5 | 玫红 | `#993556` | 7.01:1 ✅ | `#993556` | 7.01:1 | `#F5EBEE` | `#EAD6DD` |
| 6 | 亮蓝 | `#378ADD` | **3.59:1** ⚠️ 非文本 | `#1A6BA6` | **5.68:1** ✅ | `#E9F1FA` | `#D2E3F4` |

**可访问性校验结论（3 条，必读）**

1. ✅ **主色全部 ≥3:1** → 作为描边 / 竖条 / 三角 / 光标这类**非文本 UI** 使用，WCAG 1.4.11 通过。
2. ⚠️ **`#BA7517`（3.72:1）与 `#378ADD`（3.59:1）不足 4.5:1** → 这两个值**既不能用来写文字，也不能用来当承载白字的底色**（同一根因的两个触发面，详见 §11.1-3）。凡"协同色 + 文字"的组合一律切 ink 变体：`--collab-2-ink (#8F5B08 · 5.73:1)` / `--collab-6-ink (#1A6BA6 · 5.68:1)`；其余 4 色主色本身即达标，ink = 主色（**替换后视觉零变化**）。
3. ⚠️ **`#378ADD`（色相 210°）与强调蓝 `#2563EB`（色相 221°）仅差 11°**，且同为亮蓝 —— 存在"协同蓝被误读为品牌蓝 / 选中态 / 链接"的真实风险。**已内置防混淆硬规则（见 §11）**。

**可选优化（默认未启用，一行可切）**
`--collab-6-alt: #0E7490`（深青，5.36:1）已在 `tokens.css` 中提供。
理由：替换后与强调蓝色相差从 11° 拉大到 **29°**，且与青绿 `#0F6E56` 差 27°，6 色色相分布更均匀。
若要启用，把 `--collab-6` / `--collab-6-ink` / `--collab-6-bg` 三行换成 `-alt` 值即可，其余代码不用改。**因为用户已确认原色板，默认保持 `#378ADD`，靠规则防混淆。**

**协同色分配规则**
- 按**加入文档的先后顺序**分配 slot 1 → 6，**同一时刻在线的人颜色绝不重复**。
- 第 7 人及以后：复用已离开者释放的 slot；若无空闲 slot，则使用 `--neutral-700` 灰 + 姓名（标为"访客"）。
- **自己不分配协同色**：自己的光标用原生 caret，自己的选区用 `--bg-selected`。
- 头像组显示顺序：**自己永远最左**，其余按 slot 升序。

**色盲兜底（三层，缺一不可）**
1. 颜色**永远伴随姓名标签**（最高优先级，色盲用户的唯一可靠线索）
2. 同屏出现的协同元素**永远带形状差异**：文档是"3px 竖条 + 淡底"，表格是"1.5px 描边 + 右上三角"，光标是"竖线 + 胶囊"
3. 协作者面板中额外提供**文字定位描述**："李雷 — 正在编辑第 3 段" / "韩梅梅 — 正在编辑 B12"

> 诚实提示：本 6 色在**红绿色盲（deuteranopia）**下会有 5 色坍缩为深蓝灰（仅琥珀可辨）。这不是色板缺陷，是"6 色具名协同"这个命题的固有上限 —— 因此**规则 1（姓名标签）是硬性要求，不是建议**。

## 4. Typography（排版）

```css
--font-sans: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei",
             "Source Han Sans SC", "Noto Sans SC", "Hiragino Sans GB", sans-serif;
```

| Code | 13px | 400 | 1.60 | 20.8px | 0 | 公式栏、行内代码 |
| Button | 14px | **500** | — | — | 0 | 按钮（中文用 500，不用 600/700） |

### 4.3 中文排版专项

| 项目 | 规范 |
|------|------|
| **正文行高** | **1.75**（用户指定）。16px → 28px 行框；14px → 24.5px 行框 |
| **标题行高** | 1.50（中文标题行高过大反而松散，禁止用 1.75） |
| **表格行高** | 1.40（单元格内，配合 13px 字号 = 18.2px） |
| **段落间距** | 段后 12px（`--doc-para-gap`），**首行不缩进**（协同光标定位更清晰、段落锁边界更明确） |
| **列表项间距** | 4px |
| **标点挤压** | `line-break: strict` + `text-align: justify` + `text-justify: inter-ideograph`。浏览器原生 `text-spacing` 支持度不足，**不依赖自动挤压** |
| **中西文混排间距** | 中文与西文/数字之间插入 **1/4 em（0.125em）** 间隙。实现：内容生成时在交界处插入 `<span class="cjk-pad"></span>`（tokens.css 已提供该类） |
| **中文字重上限** | **600**。禁止 700/800/900 —— PingFang SC / 微软雅黑的粗体是合成字形，会发糊、字重跳变明显 |
| **中文斜体** | **禁止**。中文没有真斜体，浏览器合成斜体极难看。强调改用颜色或字重 |
| **中文标点** | 全角，占 1em；不转半角 |
| **数字与单位** | 数字走西文字体 + `font-variant-numeric: tabular-nums`（`.cjk-num` 工具类）；单位与数字之间留 1/4 em |
| **最佳行宽** | 中文每行 **35–45 字** → 文档内容列宽 **720px**（@16px ≈ 45 字） |
| **letter-spacing** | 正文 +0.01em（中文微疏排提升可读性）；标题 0；**禁止负值**（中文负字距会粘连） |
| **uppercase** | 禁止对中文使用 `text-transform: uppercase`（无意义） |

> ⚠️ **"协同色底 + 白字"必须用 `-ink`，不能用主色**（2026-09-21 修订，源自 Phase 4 实测踩坑）
> 胶囊 / 标签上的姓名是白字，此时**底色**就是文字的对比背景 —— 对比度要求同样是 **4.5:1**。
> `--collab-2 (#BA7517)` = 3.72:1、`--collab-6 (#378ADD)` = 3.59:1，**同样不达标**，且是同一根因（主色对比度 < 4.5:1）的第二个触发面。
>
> ```css
> /* ✅ 正确 */
> .collab-chip { background: var(--collab-N-ink); color: var(--neutral-0); }
> /* ❌ 错误：琥珀 / 亮蓝底 + 白字 = 3.72:1 / 3.59:1，不达 AA */
> .collab-chip { background: var(--collab-N); color: var(--neutral-0); }
> ```
>
> **代价极低，没有例外可讲**：6 色里 4 色的 ink 与主色**同值**（视觉零变化），只有琥珀（ink `#8F5B08`）与亮蓝（ink `#1A6BA6`）会变深一点点。
> 典型命中位置：**头像底 + 白字**、段首姓名胶囊、协同光标姓名标签、Excel 单元格所有者标签。同一规则见 §11.1-3。

## 8. Depth & Elevation（深度与层级）

**原则：几乎不用阴影。** 层级优先靠 `1px 边框 + 背景色差` 表达。

| 级别 | 阴影值 | 用途 |
|------|--------|------|
| Flat | `none` | 默认所有表面（卡片、表格、工具栏、文档画布） |
| Raised (`--shadow-1`) | `0 1px 2px rgba(17,24,39,.06), 0 2px 8px rgba(17,24,39,.06)` | 下拉菜单、Popover、Tooltip、分段控件选中项 |
| Floating (`--shadow-2`) | `0 4px 16px rgba(17,24,39,.10)` | 抽屉、Toast |
| Overlay (`--shadow-3`) | `0 8px 32px rgba(17,24,39,.14)` | 模态 |

**聚焦环（不用阴影表达聚焦）**
```css
outline: 2px solid var(--brand-500);
outline-offset: 2px;
/* 输入类控件额外加 */
box-shadow: 0 0 0 3px var(--brand-ring); /* rgba(37,99,235,.18) */
```

**Z-index**

| 层 | 值 |
|----|-----|

## 11. Cautions（设计禁区）

### 11.1 Never Do（违反即打回）

1. **禁止深色主题做主界面。** IDE 为 light 主题，深色仅可作为 P2 专注模式可选变体。
2. **禁止用强调蓝 `#2563EB` 表达"人"。** 蓝色只属于系统与品牌（按钮 / 链接 / 选中 / 聚焦）。
3. **禁止让协同主色 `#BA7517`（3.72:1）/ `#378ADD`（3.59:1）承担任何形式的"文字可读性"**（两者均 < 4.5:1）。
   **这是同一根因的两个触发面，不是两条独立规则 —— 只要该色出现在"文字 ↔ 背景"这一对里，就必须是 `-ink` 变体：**
   - **面 A · 用主色写文字**（深字压白底）→ 姓名文字必须用 `--collab-2-ink #8F5B08` / `--collab-6-ink #1A6BA6`。
   - **面 B · 用主色当背景、上面放白字**（白字压协同色底）→ 对比度要求同样是 4.5:1，两色**依旧不达标**。
     命中位置：头像底、段首姓名胶囊、协同光标姓名标签、Excel 单元格所有者标签。
     正确写法：`background: var(--collab-N-ink); color: var(--neutral-0)`（见 §6.5）。
     **没有例外可讲**：6 色里 4 色的 ink 与主色同值（替换后视觉零变化），只有琥珀 → `#8F5B08`、亮蓝 → `#1A6BA6` 会略变深，代价极低。
4. **禁止同一文档内给两人分配同一协同色**，必须按 slot 1–6 不重复分配。
5. **禁止协同色脱离姓名标签单独出现。** 这是色盲兜底的底线。
6. **禁止中文字重 ≥ 700**（PingFang / 雅黑合成粗体发糊）。
7. **禁止给中文使用 italic**（合成斜体）。
8. **禁止用 emoji 当图标。**
9. **禁止紫色 / 彩虹渐变背景、手绘风 SVG 人物插画。**
10. **禁止"圆角卡片 + 左侧粗彩色边框"** 这个 AI 套路组件。
11. **禁止阴影超过 2 层堆叠**；除下拉 / 抽屉 / 模态外一律 flat。
12. **禁止一屏内超过 2 个主 CTA。**
13. **禁止纯黑 `#000000` 文本**（用 `--neutral-950 #111827`）。
14. **禁止动画时长 > 300ms 且无 `prefers-reduced-motion` 兜底。**
15. **禁止在表格里使用 16px / 1.75 的文档排版参数**（会直接破坏密度）。
16. **禁止任何交互元素缺失 hover 或 focus-visible。**
17. **禁止编造数据**（"提升 300%"）与虚假社会证明（杜撰 logo 墙 / 评价）。

### 11.2 协同蓝 vs 强调蓝 —— 防混淆硬规则（本项目最高优先级）

`#378ADD`（协同亮蓝，色相 210°）与 `#2563EB`（强调蓝，色相 221°）**色相仅差 11°**，且同为亮蓝。必须用三重复用隔离：

| 维度 | 强调蓝 #2563EB | 协同色（含 #378ADD） |
|------|---------------|-------------------|
| **语义** | 系统 / 品牌（按钮、链接、选中、聚焦） | 人（永远是"某个具体的人"） |
| **空间** | chrome 层：顶栏、工具栏、侧边栏、表单、按钮 | **只在文档画布内**：段落竖条、单元格描边、光标 |
| **形状** | 实心块、下划线、2px 边框 | 3px 竖条、1.5px 描边、2px 光标竖线、右上三角 |
| **文字** | 不需要标签 | **永远伴随姓名标签** |

> 若评审仍觉得混淆，启用 `tokens.css` 中的 `--collab-6-alt: #0E7490`（深青），一行替换即可。

### 11.3 Prefer（推荐做法）

- 用 `1px 细线 + 背景色差` 做层级，而不是阴影。
- 用 **6% 品牌淡底**（`--bg-selected`）表达选中，而不是加深背景或加粗边框。
- 用 `inset box-shadow` 画选中/占用描边，**不要改 border**（避免布局跳动）。
- 数字列一律 `tabular-nums` 右对齐。
- 空状态：一句具体说明 + 一个主操作，**不用插画**。
- 占位内容用真实中文业务内容（如"2026 Q3 渠道投放复盘"），**禁止 Lorem ipsum**；数据用 `—` 占位。
- 按钮文案用行动动词（"新建文档"、"导出为 .xlsx"），不用"点击这里"、"了解更多"。

## 12. Responsive Behavior（响应式）

| 断点 | 布局行为 |
|------|---------|
| **≥1440px** | 侧边 240px + 主工作区；文件卡片 5 列；文档纸宽完整 816px |
| **1280–1439px** | 侧边 240px + 主区；卡片 4 列；文档页边距 48 → 32px |
| **1024–1279px** | 侧边折叠至 56px（仅图标）；卡片 3 列；编辑器工具条允许换行；抽屉 380 → 340px |

**适配规则**
1. 文档内容列宽**固定 720px**，窄屏时只压缩页边距：48 → 32 → 24 → 16px。
2. 表格优先保证**行号列 + 前 3 列**可见，其余横向滚动；**<1024px 关闭冻结列**。
3. 抽屉在 <768px 变为**底部升起的全屏 sheet**（圆角仅顶部 8px）。
4. 顶栏头像组：≥1280 显示 5 + `+N`；1024–1279 显示 3 + `+N`；<1024 只显示总数胶囊 + 图标。
5. 工具条图标按钮在 <1024px 允许收进 `more-horizontal` 溢出菜单，**不换行挤压文档区**。

## 13. Agent Prompt Guide（给原型构建师的生成指南）

### 13.1 关键指令（照做）

1. **先引入 `tokens.css`**，所有颜色 / 间距 / 圆角 / 阴影 / 字号一律走 `var()`，**禁止在组件里硬编码 HEX**（协同色按 slot 变量取用是唯一例外）。
2. **文档与表格是两套节奏**：Word 用 `--doc-*` 系列（16px / 1.75 / 720px / 段后 12px），Excel 用 `--grid-*` 系列（13px / 1.4 / 行高 28px / 网格线 #E6E9EF）。**绝对不要混用。**
3. **协同色按 slot 取用**：第 n 个进入的人 → `--collab-n`；**姓名文字一律用 `--collab-n-ink`**；淡底用 `--collab-n-bg`。
   **凡是"协同色底 + 白字"（胶囊 / 标签 / 头像），底色也要用 `--collab-n-ink`，不能用主色** —— 白字压主色是同一个 4.5:1 陷阱的另一个触发面（详见 §6.5、§11.1-3）。
4. **浅色主题分层**：`--bg-app #F7F8FA` 打底 → 内容区 `--bg-canvas #FFFFFF` → 靠底色差分层，**不要靠阴影**。
5. **中文排版**：正文 16px/1.75，界面 14px/1.75，表格 13px/1.4；中文字重上限 600；不用斜体；不用纯黑。
6. **图标统一**：24 viewBox / stroke 1.5 / round cap / `fill:none`，展示 16 或 20px，一套原型只用 Lucide 一套。
7. **7 屏共用 chrome**：工作台 = 顶栏 48 + 侧边 240；编辑器 = 顶栏 48 + 工具条 40（Word/Excel 各一套工具条内容）。
8. **阴影只出现 3 处**：下拉 `shadow-1`、抽屉 `shadow-2`、模态 `shadow-3`，其余 flat。
9. **每个可交互元素必须有 hover + focus-visible**（`outline: 2px solid #2563EB; outline-offset: 2px`）。
10. **内容真实**：用中文真实业务内容（"2026 Q3 渠道投放复盘"、"华东区销售明细"），禁止 Lorem ipsum；未定数据用 `—`。
